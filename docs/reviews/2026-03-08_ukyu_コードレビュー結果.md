## 改善提案 (P2)

### 横断的な提案

1. **型安全性の根本修正**: `id?: string` → `id?: number` に統一。これにより P0 の #1-3、P1 の複数項目が一括解決
2. **Zod によるスキーマバリデーション**: インポートデータ、設定値、フォーム入力の型安全なバリデーション
3. **テストカバレッジ拡充**: hooks(4ファイル)、pages(3ファイル)のテストがゼロ。重要ロジックのテスト追加
4. **GitHub Actions CI/CD**: lint → test → build → deploy の自動化パイプライン
5. **アクセシビリティ**: ARIA属性の体系的な付与、フォーカス管理の実装
6. **日付ユーティリティ**: `formatDate()` 関数に集約し、`new Date()` をDI可能に
7. **SettingsPage 分割**: 200行超の肥大化。機能ごとにコンポーネント分離
8. **auto-grant 付与月のハードコード**: 12月固定 → Settings の defaultGrantDate と連動
9. **alert() の多用**: SettingsPage で5箇所。トースト通知に置き換え推奨
10. **fiscalYear.ts が未使用**: dead code の可能性。使用するか削除

## 各観点の総評

### セキュリティ (7/10 🟡)
ローカルPWAのため外部攻撃面は限定的だが、インポート機能のバリデーション不足と確認なしデータ削除は修正すべき。

### パフォーマンス (6/10 🟡)
個人用アプリとしては問題ないが、usages全件走査のO(n*m)計算量とonChange即DB書き込みは設計上の負債。

### アーキテクチャ (6/10 🟡)
logic/hooks/components/pages の分離は良好。最大の構造的問題はDB型定義(string)とDexie実装(number)の不一致で、複数箇所にワークアラウンドが波及。

### UX/a11y (6/10 🟡)
ディスレクシア対応の設計思想（ひらがなUI、パステルカラー、UDフォント）は優秀。ARIA属性の欠如とフォーカス管理の不備が主要課題。

### DevOps (5/10 🟠)
CI/CD未設定、PWAアイコン不足、testスクリプト未定義。個人プロジェクトとしては許容範囲だが、品質保証の自動化が必要。

### コード品質 (7/10 🟡)
logicレイヤーの設計・テストは良好（80件全パス）。型不整合、DI未対応、dead codeが主な課題。
